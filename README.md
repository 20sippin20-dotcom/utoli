# Сайт «Утоли» — доставка питьевой воды в Ухте

Локальная SEO-посадочная и каталог трёх линеек воды 19 л. Заказ происходит в
мобильном приложении Utoli или у диспетчера по телефону — корзины и онлайн-оплаты
на сайте нет намеренно.

Стек: Next.js 16 (App Router, Turbopack), React 19, TypeScript в строгом режиме,
CSS Modules, Manrope через `next/font` (шрифт раздаётся локально).

**Сайт собирается в чистую статику.** `npm run build` кладёт готовые HTML, CSS,
JS и картинки в папку `out/` — сервер не нужен, подойдёт GitHub Pages или любой
статический хостинг. HTML, текст, ссылки и JSON-LD присутствуют до гидратации.

## Требования и запуск

Нужен Node.js 20+ (проверено на 24.19) и npm 10+.

```bash
npm install
```

```bash
npm run dev
```

Собрать статику и посмотреть её так, как её увидит хостинг:

```bash
npm run preview
```

### Все команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Разработка на http://localhost:3000 |
| `npm run build` | Статическая сборка в `out/` (падает без `NEXT_PUBLIC_SITE_URL`) |
| `npm run serve` | Раздача `out/` на http://localhost:3100 со сжатием, как на хостинге |
| `npm run preview` | `build` + `serve` одной командой |
| `npm run typecheck` | TypeScript в строгом режиме |
| `npm run lint` | ESLint (правила Next + запрет телефонов в разметке) |
| `npm run test` | Юнит-тесты Vitest: данные, JSON-LD, SEO, sitemap |
| `npm run check` | typecheck + lint + test одной командой |
| `npm run check:output` | Скан папки `out/` на плейсхолдеры и чужие данные |
| `npm run assets` | Пересборка ассетов из `_source-assets` (фото, логотип, иконки, QR) |
| `npm run images` | Только фотографии, логотип и иконки |
| `npm run qr` | Только QR-коды магазинов |
| `npm run audit` | Приёмочный аудит собранного сайта (нужен запущенный `serve`) |
| `npm run lighthouse` | Lighthouse mobile + desktop, отчёты в `qa/lighthouse` |

Порядок полной проверки: в одном окне `npm run preview`, в другом —
`npm run audit && npm run lighthouse && npm run shots`.

## Публикация на GitHub Pages

Хостинг бесплатный, сервер не нужен: репозиторий собирается в статику и
раздаётся с CDN GitHub.

1. Залейте проект в репозиторий GitHub, ветка `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Settings → Secrets and variables → Actions → Variables** — добавьте
   переменную `NEXT_PUBLIC_SITE_URL` со значением боевого домена, например
   `https://utoli11.ru` (без слеша на конце). Без неё сборка остановится:
   иначе canonical и sitemap уехали бы на чужой адрес.
4. Пуш в `main` запускает workflow `.github/workflows/deploy.yml`: он ставит
   зависимости, гоняет typecheck, lint и тесты, собирает статику, проверяет её
   на плейсхолдеры и публикует.

### Свой домен

Файл `CNAME` создаётся автоматически из `NEXT_PUBLIC_SITE_URL` — руками его
класть не нужно. Со стороны регистратора домена:

- для домена вида `utoli11.ru` — четыре A-записи на `185.199.108.153`,
  `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
- для `www.utoli11.ru` — CNAME на `<логин>.github.io`.

После проверки домена включите в Settings → Pages галочку **Enforce HTTPS**.

### Что было сделано ради статики

- `output: 'export'` в `next.config.mjs`;
- оптимизатор картинок Next выключен (на статике его некому запускать), вместо
  него WebP готовятся заранее скриптом `npm run images`;
- `.nojekyll` в корне сборки — без него Pages выкидывает папку `_next`,
  потому что она начинается с подчёркивания, и сайт остаётся без стилей;
- файлы предзагрузки переходов дублируются под тем именем, которое реально
  запрашивает браузер (см. комментарий в `scripts/finalize-export.mjs`);
- `X-Robots-Tag` для staging убран: заголовки на Pages не настраиваются,
  индексацию закрывает `robots.txt` через `NEXT_PUBLIC_NOINDEX`.

## Переменные окружения

Скопируйте `.env.example` в `.env.local` (локально) или задайте на хостинге.

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | **да** | Канонический домен без слеша на конце. Из него строятся canonical, Open Graph, sitemap и JSON-LD. Без неё production-сборка останавливается с понятной ошибкой; HTTP разрешён только для localhost. |
| `NEXT_PUBLIC_NOINDEX` | нет | `true` на staging и preview: robots.txt закрывает весь сайт от индексации. На production — `false` или пусто. |
| `NEXT_PUBLIC_YM_ID` | нет | ID Яндекс Метрики. Пусто — счётчик не подключается и баннер согласия не показывается. |
| `NEXT_PUBLIC_GA_ID` | нет | ID GA4, поведение такое же. |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | нет | Код подтверждения Search Console. |
| `NEXT_PUBLIC_YANDEX_VERIFICATION` | нет | Код подтверждения Яндекс Вебмастера. |

## Где что менять

Весь бизнес-контент собран в двух файлах, компоненты его только показывают.

- **`src/config/site.ts`** — телефон, VK, ссылки на магазины, город, зона доставки,
  адрес, график, способы оплаты, цены товаров, ID аналитики. **Здесь и только здесь.**
- **`src/config/routes.ts`** — маршруты, навигация, приоритеты для sitemap.
- **`src/content/faq.ts`** — вопросы FAQ. Что здесь есть, то и попадает в разметку
  `FAQPage`: размечено ровно то, что видно на странице.
- **`src/lib/status.ts`** — готовность разделов. Пока условия доставки и оплаты не
  заполнены, страница `/dostavka-i-oplata/` закрыта от индексации и не попадает в
  sitemap; после заполнения включается автоматически. Там же `qualityDocuments()` —
  список файлов документов: как только в него добавят записи, на странице
  «Документы» появятся ссылки на скачивание вместо предложения запросить их у
  диспетчера.

Правила, которые лучше не нарушать:

1. Нет данных — `null` или пустой массив. Компонент скрывает блок, а не пишет
   «уточняется» и не подставляет догадку.
2. `price: null` означает, что цены нет нигде: ни в карточке, ни в `Offer`
   структурированных данных. `0 ₽`, зачёркнутая цена и «уточняется» в разметке
   запрещены и проверяются тестами.
3. Телефон живёт в `site.dispatcherPhoneHref` / `site.dispatcherPhoneDisplay`.
   ESLint не даст написать `tel:` с номером в разметке.

### Как проставить цены

Один раз в `src/config/site.ts` у нужного товара:

```ts
price: 350,
availability: 'InStock',
sku: 'UTOLI-19L',
```

После этого цена автоматически появится в карточке, на странице товара и в
`Offer` разметки `Product`. Ничего больше править не нужно.

## Документы на продукцию

Данные взяты из документов заказчика и лежат в `src/content/documents.ts`.
Сканы — в `public/documents`, страница `/dokumenty/` собирается из них.

| Документ | Номер | Срок |
| --- | --- | --- |
| Сертификат соответствия | РОСС RU.ОС54.Н006583 | 25.12.2025 — 24.12.2028 |
| Декларация о соответствии ЕАЭС | ЕАЭС N RU Д-RU.РА11.В.97268/25 | по 22.12.2030 |
| Протокол испытаний | № ДИЛ78-07473 от 19.12.2025 | основание для обоих |

Продукция: **природная питьевая вода первой категории**, ТУ 11.07.11–001–2047955041–2025,
ТР ТС 021/2011, ТР ТС 022/2011, ТР ЕАЭС 044/2017. Срок годности 24 месяца,
хранение при +2…+20 °C.

Состав на странице документов — из протокола испытаний. Испытывался образец с
маркировкой «UTOLI» (базовая линейка): минерализация 90 мг/л, pH 6,5,
жёсткость 3 мг-экв/л, кальций 49 мг/л, магний 6,8 мг/л.

**Два расхождения, которые нужно решить владельцу:**

1. **«Высшая» или «первая» категория.** На логотипе написано «вода высшей
   категории», а в декларации и сертификате — «первой категории». На сайте
   везде стоит «первой категории», как в документах. Если логотип печатается
   на этикетках, формулировку стоит привести в соответствие с декларацией.
2. **Почтовый индекс.** В карте партнёра указан 169307, в декларации и
   сертификате — 169300, в протоколе испытаний — 169302. На сайте стоит 169300
   (совпадает в двух официальных документах). Уточните верный.

Не опубликованы: файл `ЛЕОНИД ДОК.PDF` (скан без текстового слоя, похоже на
персональный документ) и сертификат GS1 на штрихкод — это внутренние документы,
на витрине им не место. Домашний адрес ИП из документов на сайт тоже не попал:
показывается только адрес производства на Печорской, 31.

Магниевая линейка в декларации проходит как «Utoli магниевая». Отдельного
протокола именно на неё нет, поэтому содержание магния в этой линейке на сайте
не указано — только сам факт, что это вода с магнием. Если появится протокол на
магниевую воду, цифры добавляются в `src/content/documents.ts`.

## Чего ещё не хватает от владельца

Список формируется кодом — `missingBusinessData()` в `src/config/site.ts`.
На момент сдачи:

- `workingHours` — график приёма заказов (пока в шапке и контактах строки нет);
- `paymentMethods` — способы оплаты;
- `bottleDepositText` — условия по возвратной таре и залогу;
- `freeDeliveryThreshold` — порог бесплатной доставки, если он есть;
- `twoGisUrl`, `yandexBusinessUrl` — ссылки на карточки организации (пойдут в
  `sameAs`);
- `legalDisclaimer` — согласованная юридическая оговорка;
- цены на все три позиции;
- PDF самой декларации ЕАЭС: сейчас на странице выводятся её реквизиты, а
  скана нет (был прислан только в .docx). Положите файл в `public/documents`
  и укажите его в `src/content/documents.ts`;
- **фотографии большего размера.** Присланные оригиналы — 540×648 px. Этого
  хватает для карточек, но на широких экранах бутыль нельзя показать крупнее
  без апскейла.

Заполнено из документов: юридическое название, ОГРНИП, ИНН, адрес производства,
почтовый индекс, электронная почта, категория воды, ТУ, срок годности и состав.

Пока данных нет, соответствующие блоки скрыты. Плейсхолдеры в продакшен не
попадут: `npm run check:output` сканирует собранную статику на `TODO`,
`PLACEHOLDER`, `example.com`, тестовые телефоны, `0 ₽`, посторонние объёмы
бутылей и следы чужих брендов.

## Аналитика и события

Счётчики опциональны и **не загружаются до явного согласия** посетителя. Пока
`NEXT_PUBLIC_YM_ID` и `NEXT_PUBLIC_GA_ID` пустые, не грузится ничего и баннер не
показывается — показывать его не за что.

События (`src/lib/analytics.ts`, отправляются в Метрику как `reachGoal` и в GA4
как `event`):

| Событие | Когда | Параметры |
| --- | --- | --- |
| `click_googleplay` | клик по кнопке Google Play | — |
| `click_appstore` | клик по кнопке App Store | — |
| `click_phone_header` | звонок из шапки, меню, футера, hero, нижней панели | `place` |
| `click_phone_product` | звонок со страницы товара или из контактов | `product` или `place` |
| `click_vk` | переход в группу ВКонтакте | — |
| `view_product` | открытие страницы товара | `product` |
| `select_product` | «Заказать в приложении» из карточки или со страницы товара | `product`, `place` |
| `click_delivery_cta` | главный CTA hero и карточек сценариев | `place` |

Персональные данные в события не передаются: только имя события и обезличенный
контекст (slug товара, место на странице). UTM-метки в canonical не попадают.

Сканирование QR-кода на другом устройстве измерить нельзя — отдельного события
для этого нет намеренно.

## Что нужно сделать после публикации

1. Задать `NEXT_PUBLIC_SITE_URL` с боевым HTTPS-доменом и пересобрать.
2. Настроить на хостинге 301-редиректы на единственную каноническую версию:
   HTTPS и один вариант хоста (с `www` или без). Внутренние ссылки уже ведут на
   канонические адреса со слешем на конце.
3. Проверить, что на production `NEXT_PUBLIC_NOINDEX` не выставлен в `true`, а на
   staging — выставлен.
4. Открыть `/robots.txt` и `/sitemap.xml` в браузере и убедиться, что домен в них
   боевой.
5. Добавить домен в **Яндекс Вебмастер**, указать регион **Ухта**, отправить
   sitemap, вставить код подтверждения в `NEXT_PUBLIC_YANDEX_VERIFICATION`.
6. Добавить домен в **Google Search Console**, отправить sitemap, вставить код в
   `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`.
7. Создать или подтвердить карточку в **Яндекс Бизнес**: категория, регион Ухта,
   телефон, сайт, фотографии, услуги.
8. Подтвердить организацию в **2ГИС**, добавить точный URL карточки в
   `site.twoGisUrl` — он попадёт в `sameAs`.
9. Проверить индексирование ключевых страниц через 1–2 недели.
10. Следить за единообразием NAP: название, телефон и адрес должны совпадать на
    сайте, в Яндекс Бизнес, 2ГИС и VK до символа.
11. Собирать настоящие отзывы на карточках организации. Придумывать отзывы и
    рейтинги на сайте нельзя — в разметке `Product` их нет и не должно появиться
    без реальных данных и права их показывать.
12. Проверить финальную разметку через Rich Results Test, Schema Markup Validator
    и валидатор Яндекс Вебмастера.

Позиции в выдаче зависят от индексации, карточек организации, конкуренции,
отзывов, ссылок и дальнейшей работы — гарантировать их нельзя. Техническая и
контентная основа для локального продвижения подготовлена.

## Юридическая часть

- Тексты `/politika-konfidencialnosti/` описывают фактическое положение дел:
  форм на сайте нет, аналитика включается только после согласия. **Перед
  публикацией текст должен подтвердить владелец или юрист** — это не юридическая
  консультация.
- `legalDisclaimer` в конфиге пуст. Формулировку про публичную оферту нужно
  согласовать и только потом включать.
- Пользовательское соглашение не создавалось: согласованного текста нет.
- Формы обратного звонка нет. Когда она появится, потребуются согласие на
  обработку персональных данных, серверная валидация, защита от спама и
  безопасная отправка; телефон нельзя писать в URL и в параметры аналитики.

## Отступления от исходного задания

1. **Цвет главной кнопки.** В задании указан `#10A8DE`. Белый текст на нём даёт
   контраст 2.7:1 — это провал WCAG 2.2 AA, который в том же задании обязателен.
   Заливка кнопок и цвет ссылок затемнены до `#0A7BA6` (4.8:1) и `#0A7299`
   (4.95:1 на ледяном фоне). Исходный голубой остался как декоративный акцент,
   где контраст не требуется. Lighthouse Accessibility — 100.
2. **Бейджи магазинов.** Задание допускает «настоящие иконки магазинов», но
   запрещает рисовать логотипы вручную. Официальных бейджей нам не передали,
   поэтому кнопки нейтральные, без чужих товарных знаков.
3. **Слоган на логотипе.** В переданном логотипе есть строка «вода высшей
   категории». Логотип используется как есть — это фирменный ассет заказчика, —
   но в текстах и метаданных сайта это утверждение не повторяется: документов,
   подтверждающих категорию воды, у нас нет.
4. **`/dostavka-i-oplata/`** закрыта от индексации до заполнения способов оплаты и
   условий по таре, чтобы в индекс не попала страница из одних «уточните у
   диспетчера». Включается автоматически. Для пользователей страница доступна.
5. **Ступени размеров изображений** срезаны под фактические 540 px оригиналов —
   см. комментарий в `next.config.mjs`.
